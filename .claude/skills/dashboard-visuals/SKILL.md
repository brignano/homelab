# Dashboard and visuals

- **Anything with a visual choice in it follows [brignano/design](https://github.com/brignano/design)** — the shared design system, which already names `homelab` as a tool-tier consumer. Take colour from its tokens rather than picking one: identity is its `mark` hue (larch amber), and it only ever inks a graphic, never a control. `docker/dashboard/icons/` is the worked example, including why a favicon is the one place its "never hardcode a hex" rule cannot hold.
- **Page icons follow the standard `life` sets** (`scripts/gen-icons.mjs` there, `scripts/gen-dashboard-icons.py` here): the SVG is the real mark — transparent ground, `prefers-color-scheme` step, because a filled tile disappears against a tab strip that matches it — and the rasters (`.ico`, `apple-touch`, 32px PNG) take an ink ground for the surfaces that put the icon somewhere we do not control. Safari probes `/favicon.ico` and `/apple-touch-icon.png` at the root without reading markup, so those paths have to answer; the Caddyfile points them at the mark. **An installed app reads none of that** — Chrome draws its window titlebar, taskbar entry and install dialog from the web app *manifest*, never from `rel="icon"` — so `/site.webmanifest` is rewritten onto ours the same way, and it lists rasters only (192, 512, and a 512 inset 10% a side for `maskable`), for the same ink-ground reason. Fixing the tab icon and fixing the app window are two separate pieces of work; check both.
- **Third-party marks stay as their projects draw them.** The home page's tile icons are vendored into `docker/dashboard/icons/` by `scripts/update-tile-icons.sh` rather than fetched from a CDN by the browser — a dashboard that needs the internet to render is useless on the day the internet is what broke. Adding a service means a tile in `docker/dashboard/site/services.json` (`icon`, and a `probe` that is a blackbox target in `prometheus.yml`) and a run of that script; `scripts/check-dashboard.sh` fails CI if the file, the probe or the Caddyfile site is missing. A mark drawn in one dark ink sets `inkIcon` so the page recolours it with the text colour; a mark upstream draws twice uses `icon` (`-on-dark`) and `iconLight` (`-on-light`).
- **The home page is plain files, styled from the system and nothing else** (homelab#395 replaced Homepage). `docker/dashboard/site/` (index.html, app.css, app.js, services.json) is served by Caddy at the bare domain, with no container. `scripts/update-design-tokens.sh` vendors `tokens.css` and Geist into `docker/dashboard/assets/`; `app.css` imports them and uses only their variables, including the `mark-teal` / `mark-violet` / `mark` accents for graphics. Status is a word in a pill (Up, Down, Asleep), never a dot alone. Every number comes from Prometheus through the page's own read-only `/api/prom/` route; open-work totals reuse the Work page's `data.js`. `homepage-palette.css` is a leftover the token script still generates.
- **A new file under `docker/dashboard/icons/` is live on the next pull.** Caddy serves the home page's `site/` and `icons/` from directory mounts, so there is no container to restart (Homepage's need for one is gone with it).
- **A container that owns a bind-mounted config directory writes to it.** Homepage used to drop 0-byte skeletons into its config directory and stop `git pull`; `repo-sync.sh` still clears that narrow case (untracked, empty, added by an incoming commit) for any directory. Keep config mounts read-only where the image allows it.
